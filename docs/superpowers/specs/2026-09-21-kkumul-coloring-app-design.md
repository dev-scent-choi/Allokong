# 꼬물꼬물 색칠공부 앱 — 설계 문서

- 작성일: 2026-09-21
- 상태: 승인됨 (구현 계획 작성 대기)
- 선행 문서: `kkumul_uiux_project_plan.docx` (UI/UX 기획서), `index.html` (클릭 프로토타입)

## 1. 배경

UI/UX 기획서와 클릭 프로토타입이 이미 존재한다. 기획서의 진행 관리표 01~07은 완료, 08(사용성 검토)은 대기 상태다. 이 문서는 그 기획을 구현 가능한 기술 설계로 옮긴 것이며, 기획서를 정본으로 삼되 1단계 범위에서 커뮤니티 기능을 제외한다.

기획서 대비 변경 사항은 16장에 정리했다.

## 2. 제품 목표

기획서의 목표를 그대로 승계한다.

1. 유아는 읽기보다 큰 그림과 한 번의 터치로 바로 색칠을 시작한다.
2. 아동은 자신이 그린 스케치를 도안으로 바꾸고 작품을 안전하게 나눈다.
3. 랭크는 실력 경쟁이 아니라 완성·창작·꾸준함을 보상한다.

## 3. 범위

### 1단계 포함

- 내장 도안 색칠 (탭 채우기 + 브러시 + 스티커 + 지우개 + 되돌리기)
- 사진 → 도안 변환 (온디바이스)
- 연령 분기 (유아 3~5세 / 아동 6~9세)
- 랭크·주간 미션·배지 (기기 로컬)
- 작품 저장, 사진첩 내보내기, 보호자 게이트를 거친 시스템 공유
- 5탭 고정 하단 내비게이션, 세로·가로 양방향

### 1단계 제외

- 전체 공개 피드, 댓글, 친구 기능 — UI에 "준비 중"으로 표시만 하고 동작하지 않는다
- 계정, 서버, 클라우드 동기화
- 원격 도안 다운로드 — 인터페이스만 두고 구현체는 내장 소스 하나
- 광고, 인앱 결제
- 다국어 — 한국어 고정, 문자열 분리 구조만 유지

앱은 1단계에서 네트워크를 전혀 사용하지 않는다. 개인정보를 수집하지 않으며, 아이의 이미지가 기기 밖으로 나가는 유일한 경로는 성인이 보호자 게이트를 통과해 띄운 시스템 공유 시트다.

## 4. 기술 스택

| 항목 | 선택 | 비고 |
|---|---|---|
| 프레임워크 | Flutter | 화면 대부분이 커스텀 렌더링이고 Skia를 직접 제어할 수 있음 |
| 렌더링 | `CustomPainter` + fragment shader | 채움 레이어를 셰이더로 처리 |
| 영역 표현 | 래스터 인덱스맵 | 5장 |
| 이미지 처리 | 순수 Dart (`package:image`) + Isolate | 성능 미달 시 OpenCV FFI로 교체, 인터페이스는 고정 |
| 로컬 저장 | 파일 시스템 (JSON + PNG) | DB 없음, 11장 |
| 에셋 생성 | Dart CLI + Python (AI 생성 단계만) | 6장 |

## 5. 도안 데이터 포맷

도안 하나는 파일 세 개로 구성되며, **내장 도안과 사용자 생성 도안이 완전히 같은 포맷**을 쓴다. 색칠 엔진은 둘을 구분하지 않는다.

```
<dohan>/
  lineart.png      알파 채널이 있는 검정 선화 (1024)
  lineart@2x.png   고밀도 기기용 선화 (2048). 내장 도안만 제공하며 사용자 도안에는 없다
  regions.png      영역 인덱스맵 (1024 고정)
  meta.json        메타데이터
```

### 5.1 인덱스맵 인코딩

`regions.png`는 각 픽셀에 영역 ID를 담는다. RGBA 8bit PNG를 쓰되 색상으로 읽지 않는다.

| 채널 | 의미 |
|---|---|
| R | 영역 ID 하위 8bit |
| G | 영역 ID 상위 8bit |
| B | 0 (예약) |
| A | 255 |

| ID | 의미 |
|---|---|
| 0 | 선 픽셀 — 칠할 수 없고 브러시도 얹히지 않는다 |
| 1 | `BACKGROUND` — 도안 바깥. 칠할 수 없다 |
| 2 이상 | 칠할 수 있는 영역 |

최대 65,535개 영역을 표현한다. 품질 게이트가 120개로 제한하므로 실제로는 여유가 크다.

**제약: 인덱스맵은 반드시 nearest-neighbor로만 샘플링한다.** 선형 보간을 쓰면 영역 경계에서 ID 17과 23이 섞여 20이 산출되고 엉뚱한 영역이 칠해진다. 조용히 발생하고 재현이 어려운 버그이므로, 텍스처 생성 지점과 셰이더 양쪽에 못을 박고 15장의 테스트로 잠근다.

### 5.2 meta.json

```json
{
  "id": "dino-tri-01",
  "title": "삼각 공룡",
  "category": "dinosaur",
  "source": "bundled",
  "canvasSize": [1024, 1024],
  "regionCount": 23,
  "difficulty": 2,
  "suggestedPalette": ["#63b98b", "#f1bd45", "#6caee0"],
  "regionCentroids": { "2": [412, 330], "3": [510, 288] },
  "createdAt": "2026-09-21T00:00:00Z"
}
```

`source`는 `bundled` 또는 `user`. `regionCentroids`는 미완성 영역 힌트 표시에 쓴다.

### 5.3 해상도

- 도안 캔버스 기준 해상도: 1024 × 1024
- 고밀도 기기용 선화: 2048 × 2048 (`lineart@2x.png`)
- 인덱스맵은 1024 고정 — 좌표를 스케일해서 조회한다
- 내보내기 해상도: 2048 × 2048

## 6. 파이프라인 — 한 벌만 구현한다

빌드 타임 에셋 생성과 온디바이스 사진 변환은 같은 알고리즘이다. 두 번 구현하지 않는다.

```
packages/dohan_core/   순수 Dart, Flutter 의존 없음
    보정 → 이진화 → 선 보정 → 영역 라벨링 → 정리 → 인덱스맵
         ↑                                        ↑
    Flutter 앱                              Dart CLI 도구
    (사용자 사진 변환, 8장)                  (내장 도안 배치 생성)
```

Python은 AI 이미지 생성 단계에만 쓴다 (프롬프트 실행 + 파일 입출력). 알고리즘이 한 곳에 있으므로 누수 회귀 테스트 한 벌이 양쪽을 동시에 지킨다.

### 6.1 단계

| 단계 | 처리 | 목적 |
|---|---|---|
| 1. 생성 | (빌드 타임만) 카테고리별 프롬프트로 선화 생성 | — |
| 2. 정규화 | 그레이스케일 → adaptive threshold 이진화 → 목표 해상도 리샘플 | 회색 안티에일리어싱이 영역을 오염시키는 것을 막는다 |
| 3. 선 보정 | morphological closing, 커널 크기는 추정 선 두께에 비례 | **끊긴 선을 메운다. 누수를 막는 핵심 단계** |
| 4. 영역 라벨링 | 비(非)선 픽셀에 connected components (union-find) | 칠할 수 있는 영역을 확정한다 |
| 5. 정리 | 면적 임계값 미만 파편은 최대 인접 영역에 병합. 캔버스 테두리에 닿는 영역은 ID 1(`BACKGROUND`)로 예약 | 파편 제거, 배경 구분 |
| 6. 검수 | 영역마다 랜덤 색을 입힌 미리보기 PNG 산출 | 빌드 타임: 사람이 눈으로 판정. 온디바이스: 사용자 확인 화면 |
| 7. 패키징 | `lineart.png`, `regions.png`, `meta.json` 산출 | — |

### 6.2 품질 게이트

빌드 타임에는 통과한 도안만 사람이 최종 승인한다. 온디바이스에서는 실패 시 사용자에게 재촬영을 안내한다.

| 조건 | 판정 | 근거 |
|---|---|---|
| 영역 수 < 4 | 리젝트 | 너무 단순하거나 라벨링 실패 |
| 영역 수 > 120 | 리젝트 | 선이 지저분함. 아이가 칠하기 어렵다 |
| `BACKGROUND` 면적 < 캔버스의 60% | 리젝트 | **선이 새고 있다는 신호** |
| 최소 영역의 **내접원** 지름 < 64dp 환산 | 경고 후 병합 | 손가락으로 누를 수 없다. 외접원이 아니라 내접원으로 재는 이유는, 가늘고 긴 영역은 외접원이 커도 누를 수 없기 때문이다 |

### 6.3 AI 생성 프롬프트 (빌드 타임)

카테고리는 동물, 자동차, 공룡, 캐릭터 네 가지다. 캐릭터는 **자체 오리지널만** 사용한다 — 기존 IP를 쓰지 않는다.

프롬프트 템플릿 뼈대:

```
thick black outline coloring book page for toddlers,
<subject>, closed shapes, no shading, no gradients, no texture,
pure white background, bold uniform line weight, centered composition
```

생성 모델의 상업적 이용 조건은 모델 선정 시 별도로 확인한다.

## 7. 렌더링 엔진

### 7.1 레이어 구성

아래에서 위 순서로 합성한다.

```
5. 스티커 레이어   오브젝트 목록, 선화보다 위 (스티커가 선에 가리면 안 됨)
4. 선화 레이어     lineart.png, 알파 블렌드
3. 브러시 레이어   오프스크린 ui.Image, 스트로크 누적
2. 채움 레이어     fragment shader (regions.png + 팔레트 LUT)
1. 흰 배경
```

### 7.2 채움 (양동이)

1. 탭 좌표 → 캔버스 좌표 변환 → `regions.png`에서 픽셀 1개 읽기 → 영역 ID 획득. **O(1)**
2. ID가 0(선) 또는 1(`BACKGROUND`)이면 무시한다
3. CPU 측 `fills: Map<int, Color>`를 갱신하고, 이를 팔레트 LUT 텍스처에 1픽셀 기록
4. 셰이더가 픽셀마다 `regions`를 샘플링해 ID를 얻고, LUT에서 색을 조회해 출력

런타임에 영역을 재계산하지 않으므로 항상 60fps를 유지하며, 누수가 구조적으로 발생할 수 없다.

**팔레트 LUT**: 256 × 256 RGBA 텍스처. 영역 ID `n`은 좌표 `(n % 256, n ~/ 256)`에 대응한다. 알파 0은 "아직 칠하지 않음"을 뜻한다.

### 7.3 브러시 (크레용 · 붓)

브러시 레이어를 합성할 때 셰이더가 픽셀별로 `regionId >= 2`인지 확인한다. 결과적으로:

- 검은 선 위에는 브러시가 얹히지 않는다 → 도안 윤곽이 항상 살아있다
- 도안 바깥 배경에도 칠해지지 않는다 → 화면이 지저분해지지 않는다
- **영역 경계는 넘나들 수 있다** → 아이가 한 번에 쓸어서 넓게 칠할 수 있다

영역 단위로 가두지 않는 것은 의도된 선택이다. 아이에게 더 관대하고 자연스러우며, 기획서의 "실패를 쉽게 되돌리는가" 기준에 부합한다.

크레용과 붓은 스트로크 텍스처와 알파 곡선만 다르고 마스킹 로직은 동일하다.

### 7.4 스티커

래스터로 굽지 않고 오브젝트 목록으로 유지한다.

```json
{ "stickerId": "star-01", "x": 512, "y": 300, "scale": 1.2, "rotation": 0.15 }
```

개별 이동·삭제가 가능하고, 되돌리기가 단순하며, 저장 용량이 사실상 0이다.

### 7.5 지우개

현재 선택된 레이어에서 지운다. 유아 모드에는 지우개가 없다 — 되돌리기만 제공한다.

- 브러시 레이어 위: 해당 픽셀의 알파를 0으로
- 채움 영역 위: 그 영역의 fill을 제거 (미채색 상태로)
- 스티커 위: 해당 스티커 오브젝트 삭제

### 7.6 되돌리기

명령 스택으로 구현한다.

| 명령 | 보관 내용 | 크기 |
|---|---|---|
| `FillCommand` | `{regionId, 이전색, 새색}` | 수십 바이트 |
| `StrokeCommand` | 스트로크의 점 목록 + 도구·색·굵기 | 수 KB |
| `StickerCommand` | 추가/이동/삭제 전후 상태 | 수십 바이트 |

`StrokeCommand`는 되돌릴 때 레이어를 지우고 남은 스트로크를 리플레이한다. 레이어 전체를 스냅샷하는 것보다 메모리를 훨씬 적게 쓴다. 스택 깊이는 50으로 제한한다.

유아 모드는 기획서대로 한 단계 되돌리기만 노출하지만, 내부 스택은 동일하다.

## 8. 온디바이스 도안 변환 (만들기)

기획서의 5단계 흐름에 대응한다. 6장의 `dohan_core`를 그대로 호출한다.

| 단계 | 화면 | 처리 | 연령 분기 |
|---|---|---|---|
| 1 | 사진 선택 | 촬영 또는 앨범 선택 | 공통 |
| 2 | 변환 중 | 사각형 검출 → 원근 보정 → 그림자 제거(division normalization) | 자동 |
| 3 | 변환 중 | 이진화 + 선 추출 (`dohan_core` 2단계) | 자동 |
| 4 | 변환 중 | 선 끊김 보정 (`dohan_core` 3단계) | 유아=전자동 / 아동=「빈 공간 메우기」 슬라이더 |
| 5 | 변환 중 | 영역 라벨링 → 인덱스맵 (`dohan_core` 4~5단계) | 자동 |
| 6 | 확인 | 변환 전/후 비교 + 영역 확인 미리보기 | 유아=생략하고 바로 색칠 / 아동=선 굵기 조정 가능 |
| 7 | 저장 | `dohans/<uuid>/`에 저장 후 색칠 화면으로 | 공통 |

**단계 소유권**: 2단계(사각형 검출·원근 보정·그림자 제거)는 사진 입력에만 필요한 전처리이므로 `lib/convert/`가 소유한다. 3단계부터가 `dohan_core`이며, 내장 도안 생성 경로는 2단계를 건너뛴다.

**성능**: 1024px 기준 연결요소 라벨링은 순수 Dart + Isolate로 수백 밀리초 수준이다. 진행 표시로 덮는다. 측정 결과가 2초를 넘으면 OpenCV FFI 구현으로 교체하되 `dohan_core`의 인터페이스는 바꾸지 않는다.

**실패 처리**: 품질 게이트(6.2)에 걸리면 "선이 잘 안 보여요. 더 밝은 곳에서 다시 찍어볼까요?"처럼 아이가 이해할 수 있는 안내와 재촬영 버튼을 제공한다. 실패 원인별 문구를 구분한다 (어두움 / 선이 흐림 / 너무 복잡함).

**프라이버시**: 촬영한 원본 사진은 변환에만 쓰고 저장하지 않는다. 산출된 도안 세 파일만 남는다.

## 9. 연령 분기

보호자가 `내 정보`에서 연령대를 설정한다. 기본값은 유아다.

| | 유아 3~5세 | 아동 6~9세 |
|---|---|---|
| 도구 | 양동이 + 되돌리기 | 양동이 · 크레용 · 붓 · 스티커 · 지우개 |
| 변환 확인 | 생략, 바로 색칠 | 선 굵기 · 빈 공간 메우기 조절 |
| 팔레트 | 8색 고정 | 확장 팔레트 (8색 × 3 명도 = 24색) |
| 되돌리기 | 한 단계 | 50단계 |

`AgeMode` 플래그 하나로 UI가 갈라지고 엔진은 동일하다.

**기본 팔레트 8색** (프로토타입 값 승계):

| 이름 | 값 |

## 10. 화면 명세

### 10.1 고정 하단 내비게이션

기획서의 원칙을 그대로 따른다.

```
놀기 · 모아보기 · [＋ 만들기] · 랭크 · 내 정보
```

- 모든 주요 화면에서 같은 위치에 고정한다. 스크롤 중에도 사라지지 않는다
- 탭은 다섯 개로 제한한다. 아이콘과 짧은 한글 라벨을 함께 쓴다 — 색만으로 의미를 전달하지 않는다
- `만들기`는 중앙의 큰 더하기 버튼으로 분리한다
- 색칠 중 다른 탭을 누르면 자동 저장한 뒤 이동을 확인한다
- 가로 모드에서는 우측 세로바로 전환하고 캔버스가 화면 대부분을 차지한다

### 10.2 화면별 명세

| 화면 | 목적 | 필수 요소 | 주요 전환 |
|---|---|---|---|
| 놀기 | 가장 빠른 시작 | 오늘의 큰 도안, 이어 그리기, 카테고리별 도안, 오늘의 미션 행 | 도안 탭 → 색칠 |
| 색칠 | 몰입과 완성 | 큰 캔버스, 접히는 도구 패널, 팔레트, 되돌리기, 상단 고정 `완성` | 완성 → 저장 시트 |
| 만들기 | 스케치를 도안화 | 촬영·앨범, 변환 진행 표시, 확인 미리보기 | 저장 → 색칠 또는 내 도안 |
| 모아보기 | 작품 회상과 재시작 | 내 작품, 내 도안, 즐겨찾기, 빈 상태 안내 | 작품 → 재색칠 또는 공유 |
| 랭크 | 긍정적 동기 | 색칠·창작·꾸준함 3칸, 배지, 주간 미션 | 미션 → 도안 또는 만들기 |
| 내 정보 | 보호자 안전 관리 | 연령대, 닉네임, 공개 범위 기본값, 음소거, 데이터 초기화 | 저장 후 이전 화면 |

### 10.3 아동 UX 제약

설계 제약으로 고정한다.

- 터치 타겟 최소 64dp. 6.2의 최소 영역 기준과 같은 값이다
- 글을 못 읽는 연령을 전제로 아이콘·색·소리로 의미를 전달하되, 색만으로 전달하지 않는다
- 파괴적 동작(전체 지우기, 작업 중 나가기)은 확인 단계를 거친다
- 효과음 피드백(칠할 때, 완성 시)을 제공하고 음소거 토글을 둔다
- 화면 내부의 뒤로 이동은 `← 이전`으로 통일한다. 앱 종료 행동과 혼용하지 않는다

## 11. 데이터 저장

작품과 도안은 각각 **자기 완결적인 폴더 하나**다.

```
<앱 문서 디렉터리>/
  dohans/<uuid>/
    lineart.png
    regions.png
    meta.json
  artworks/<uuid>/
    artwork.json      { dohanId, fills, updatedAt, ... }
    brush.png         브러시 레이어 (없으면 파일 없음)
    stickers.json     스티커 오브젝트 목록 (없으면 파일 없음)
    thumb.png         갤러리 썸네일
  stats.json          랭크·미션·배지
  settings.json       연령대, 닉네임, 공개 범위 기본값, 음소거
```

### 11.1 중앙 인덱스를 두지 않는다

갤러리 목록은 디렉터리를 스캔해서 만든다. 중앙 인덱스 파일이 하나 있으면 그것이 손상됐을 때 아이의 작품 전체가 한 번에 사라진다. 작품 수십 개 규모에서 스캔 비용은 체감되지 않고, 폴더 하나가 손상돼도 나머지는 멀쩡하다.

갤러리에 검색·태그 기능이 붙는 시점에 SQLite로 올린다. 저장소를 인터페이스(`ArtworkRepository`)로 분리해 두므로 교체 비용이 작다.

### 11.2 자동 저장

- 명령 실행마다 1초 디바운스
- 앱이 백그라운드로 갈 때 즉시
- 탭 이동 시 즉시 (10.1)

아이는 저장 버튼을 누르지 않는다. `artwork.json`은 임시 파일에 쓰고 rename하는 원자적 쓰기로 갱신한다.

### 11.3 도안 카탈로그

`DohanSource` 인터페이스 뒤에 둔다.

- `BundledDohanSource` — 앱 번들 내장 도안
- `UserDohanSource` — 사용자가 변환한 도안
- (미구현) `RemoteDohanSource` — 나중에 끼워 넣을 수 있게 인터페이스만 정의

## 12. 랭크 · 미션 · 배지

`stats.json` 파일 하나로 관리하며 서버를 쓰지 않는다.

```json
{
  "coloringCount": 12,
  "creationCount": 3,
  "streakDays": 5,
  "lastActiveDate": "2026-09-21",
  "badges": ["first-artwork", "first-creation", "three-day-streak"],
  "weeklyMission": { "id": "use-three-colors", "progress": 2, "target": 3, "weekOf": "2026-09-21" }
}
```

### 12.1 랭크 화면 지표

**색칠 · 창작 · 꾸준함 세 칸.** 기획서에 있던 `칭찬`은 커뮤니티를 전제한 지표이므로 1단계에서 제외한다. 커뮤니티가 열릴 때 별도로 정의한다.

| 지표 | 정의 |
|---|---|
| 색칠 | 완성 버튼을 누른 작품 수 |
| 창작 | 사진에서 변환해 저장한 도안 수 |
| 꾸준함 | 연속 사용 일수 |

### 12.2 주간 미션

내장 규칙 목록에서 매주 하나를 롤링한다. 압박이 아닌 제안으로 표현한다 — 실패 상태를 만들지 않고, 미완료 미션은 조용히 다음 주 것으로 교체된다.

예: 색 3가지로 도안 완성하기 · 새 도안 하나 만들기 · 공룡 도안 칠해보기 · 이틀 연속 색칠하기

### 12.3 배지

완성·창작·꾸준함 각 축의 누적 이정표에서 부여한다 (첫 작품, 작품 10개, 첫 창작, 3일 연속, 7일 연속 등). 잃을 수 없고, 남과 비교되지 않는다.

## 13. 공유와 보호자 게이트

### 13.1 공개 범위

기획서의 4단계 UI를 유지하되 1단계에서는 둘만 활성화한다.

| 범위 | 1단계 | 동작 |
|---|---|---|
| 개인 | 활성 | 기기 안에만 보관 |
| 가족 | 활성 | 보호자 게이트 → 시스템 공유 시트 (사진첩, 메신저, 인쇄) |
| 친구 | 잠금 | "준비 중" 표시 |
| 전체 공개 | 잠금 | "준비 중" 표시 |

기본값은 기획서대로 비공개(개인)다. 잠긴 항목을 회색으로 보여주는 것은 나중에 열 때 아이와 보호자가 이미 개념을 알고 있게 하기 위함이다.

### 13.2 보호자 게이트

- 적용 지점: 외부 공유, `내 정보` 진입, 데이터 초기화
- 방식: 한 자리 × 한 자리 곱셈 문제 + 숫자 키패드
- 3회 실패 시 30초 잠금
- 사진첩 저장은 기기 밖으로 나가지 않으므로 게이트 없이 허용한다

### 13.3 내보내기 품질

공유·사진첩 저장 시 화면 캔버스를 캡처하지 않고 **2048px 오프스크린으로 재렌더링**한다. 화면 캡처를 쓰면 기기 해상도에 따라 결과물 품질이 달라지고 인쇄 시 뭉갠다.

| `lib/library/` | 도안 카탈로그 (`DohanSource`) | core |

| `lib/progress/` | 랭크·미션·배지 | core |

## 15. 테스트 전략

TDD로 진행한다. 이 프로젝트에서 테스트가 실제로 값을 하는 지점은 다음과 같다.

| 대상 | 테스트 | 우선순위 |
|---|---|---|
| `dohan_core` | 일부러 선을 끊어놓은 픽스처 → 선 보정 후 영역 수와 `BACKGROUND` 비율 단언 (**누수 회귀 테스트**) | 최상 |
| `dohan_core` | 품질 게이트 경계값 (영역 3/4/120/121개) | 높음 |
| 좌표 매핑 | 확대·이동·nearest 샘플링이 걸린 상태에서 탭 좌표가 올바른 영역을 짚는지 | 최상 |
| 되돌리기 | fill·stroke·sticker·erase 혼합 시퀀스 → 되돌리기 → 상태 일치 | 높음 |
| 저장 | 저장 → 로드 → 동일. 쓰기 도중 강제 종료 시나리오 포함 | 높음 |
| 렌더링 | 골든 이미지 — 픽스처 도안 + 고정 fills → 결과 비교 | 중간 |
| 변환 흐름 | 저조도·기울어진 사진 픽스처 → 게이트 판정과 안내 문구 매칭 | 중간 |
| 위젯 | 탭하면 색이 바뀐다 / 보호자 게이트가 오답을 막는다 / 탭 이동 시 자동 저장된다 | 중간 |
| 연령 분기 | 유아 모드에서 지우개·스티커가 노출되지 않는다 | 중간 |

## 16. 기획서 대비 변경 사항

| 항목 | 기획서 | 이 문서 | 사유 |
|---|---|---|---|
| 전체 공개 · 댓글 · 친구 | 포함 | **1단계 제외**, UI에 잠금 표시 | 아동 UGC 공개는 상시 모더레이션·신고 처리·연령 확인·법적 대응 조직을 요구한다. 앱 자체보다 큰 프로젝트이고 한번 열면 닫기 어렵다 |
