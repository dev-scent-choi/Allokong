# 셸과 모아보기 설계 (계획 4)

**상위 스펙**: `docs/superpowers/specs/2026-09-21-kkumul-coloring-app-design.md`
이 문서는 그 스펙의 **10장(화면 명세) · 11장(데이터 저장) · 9장(연령 분기)** 을 계획 4 범위에서
구체화하고, 세 군데는 **의도적으로 다르게 정한다**(2절). 충돌하면 계획 4 범위에서는 이 문서가 우선한다.

**전제**: 계획 3 완료 상태. 앱 176 테스트, 다섯 도구와 연령 분기가 동작하지만 **화면이 하나뿐이고
내장 도안도 하나뿐이다.** 아이가 다른 그림을 고르거나 전에 그린 것을 볼 방법이 없다.

**함께 읽을 것**: 후속 문서 세 개 — `2026-09-21-dohan-core-pipeline-followups.md`,
`2026-09-25-coloring-engine-followups.md`, `2026-09-30-brush-sticker-tools-followups.md`.
이 설계가 그중 **세 항목을 구조로 은퇴시킨다**(4절).

## 1. 범위

**만든다**: 하단 내비게이션 셸, `놀기`(도안 고르기), `모아보기`(내 작품), `내 정보`(연령·데이터 초기화),
작품 썸네일, 내장 도안 12장.

**만들지 않는다**:

| 항목 | 어디로 | 왜 |
|---|---|---|
| `만들기` (사진 → 도안) | 계획 5 | 스펙 8장 전체. 새 `lib/convert/`(사각형 검출·원근 보정·그림자 제거)가 필요하다 |
| `랭크` · 미션 · 배지 | 계획 6 | 스펙 12장 |
| 공유 · 보호자 게이트 | 계획 6 | 스펙 13장 |
| 닉네임 · 공개 범위 기본값 | 계획 6 | 랭크와 공유가 있어야 의미가 생긴다 |
| 모아보기의 `내 도안` | 계획 5 | 10.2 의 필수 요소지만 **아이가 만든 도안**을 뜻한다. 만드는 화면이 계획 5 라 지금은 항상 비어 있다 |
| 음소거 | **미배정** | 10.3 이 요구하지만 **효과음 자체가 어느 계획에도 배정되지 않았다.** 없는 것을 끄는 스위치를 만들지 않는다 — 둘은 같은 계획에서 함께 와야 한다 |
| 즐겨찾기 | 미정 | 10.2 의 필수 요소지만 상세가 없다. 작품 수십 개에 최신순 정렬이면 찾는 데 문제가 없고, 나중에 `artwork.json` 의 불린 하나로 붙는다 |
| 작품별 삭제 | **넣지 않는다** | 3절 참조 |
| 가로 모드 | 미정 | 스펙 10.1 이 요구하지만 세로 예산부터 맞춘다. 별도 작업 |

`만들기` 와 `랭크` 는 **내비에 자리를 만들어 두고 자리표시자 화면**을 둔다 — 이유는 5.1절.

## 2. 상위 스펙과 다르게 정한 것

### 2.1 색칠 화면에서는 내비를 숨긴다 (10.1절)

상위 스펙 10.1: *"모든 주요 화면에서 같은 위치에 고정한다"*, 그리고 *"색칠 중 다른 탭을 누르면
자동 저장한 뒤 이동을 확인한다"*.

**다르게 한다.** 색칠은 탭이 아니라 셸 위에 **띄우는 화면**이고, 그동안 내비는 보이지 않는다.

근거는 세로 예산이다. 320×640 에서 색칠 화면은 이미 꽉 차 있다(계획 3 실측):
앱바 64 + 캔버스 350 + 도구 줄 64 + 상황별 영역 128 + 제스처 34 = 640.
내비는 10.3 의 64dp 가 탭에도 걸리므로 64dp 이고, 넣으면 **캔버스가 350 → 286dp** 로 줄어
본문의 45% 가 된다. 색칠 앱에서 그림 그릴 자리가 절반 아래로 내려간다.

덤으로 10.1 의 *"색칠 중 다른 탭을 누르면 자동 저장한 뒤 이동을 확인한다"* 는 요구가
**사라진다** — 누를 탭이 없다. 상위 스펙 10.2 가 색칠 화면의 목적을 *"몰입과 완성"* 이라고
적었으므로, 몰입 중에 다른 화면이 없어지는 것은 그 목적과 일관된다.

나가는 길은 상단의 `완성` 버튼(10.2 가 이미 요구한다)과 기기 뒤로가기다.

### 2.3 색칠 화면을 나갈 때 확인하지 않는다 (10.3절)

2.1 이 없앤 것은 10.1 의 **탭 전환** 확인뿐이다. 10.3 의 *"파괴적 동작(전체 지우기, 작업 중
나가기)은 확인 단계를 거친다"* 는 `완성` 과 뒤로가기에 그대로 걸린다. 그것도 **하지 않는다.**

이유는 그 동작이 이 앱에서 파괴적이지 않기 때문이다. 자동 저장이 있어서 나가도 잃는 것이
없고, 다시 열면 채움·브러시·스티커가 그대로 돌아온다(계획 3 에서 세 파일 복원을 다 붙였다).
잃는 것이 없는 동작에 확인을 붙이면, 글을 못 읽는 아이는 읽을 수 없는 대화상자를 만나
아무 버튼이나 누르는 법을 배운다 — 그러면 **진짜** 파괴적인 동작의 확인도 같이 무력해진다.

확인 단계는 실제로 되돌릴 수 없는 곳에만 남긴다: 전체 지우기와 `내 정보` 의 데이터 초기화
(8절, 두 단계 확인). 둘 다 어른이 읽을 수 있는 자리다.

### 2.2 카테고리 `character` 를 `shape` 로 (5.2절)

상위 스펙 5.2 는 카테고리를 `animal · car · dinosaur · character` 로 정한다.
계획 4 의 내장 도안은 **코드로 그린 자리표시자**라 캐릭터를 그릴 수 없고, 그려 봤자 도형이다.
`character` 자리에 `shape`(별·하트·꽃 같은 단순 도형)를 둔다.

**이것은 값만 바꾸는 변경이 아니다.** `DohanMeta.category` 자체는 `String` 이지만
카테고리 목록을 **세 군데가 못박고 있다**:

- `tools/dohan_cli/bin/dohan.dart:129` — `allowed: ['animal', 'car', 'dinosaur', 'character']`.
  고치지 않으면 `--category=shape` 가 CLI 에서 거부되어 도안 생성이 멈춘다.
- `packages/dohan_core/lib/src/dohan_package.dart:14` — 같은 목록을 적은 문서 주석.
- `tools/dohan_gen/prompts.py:3` — `CATEGORIES = ("animal", "car", "dinosaur", "character")`,
  거기에 `character` 전용 프롬프트와 "기존 프랜차이즈를 닮지 않게" 하는 안전 문구까지
  딸려 있다. **계획 4 는 이것을 고치지 않았다** — 실행 중에야 발견했고, `dohan_gen` 은
  앱이 부르지 않는 별도 도구라 당장 깨지는 것이 없다. 후속 문서 §2 참조.

둘 다 `character` → `shape` 로 바꾼다. 진짜 캐릭터 도안이 생기면 목록에 도로 넣는다
(둘은 배타적이지 않다 — 그때는 다섯 개가 된다).

**덤으로 고칠 데이터 하나**: 현재 유일한 내장 도안 `flower-01` 의 `meta.json` 은
`"category": "animal"` 인데 내용은 동심원 꽃이다. `--category` 를 안 줘서 기본값
`animal` 이 들어간 것이다. `shape` 로 바로잡는다 — 그러지 않으면 `동물` 칸에 꽃이 뜬다.

## 3. 정해진 것 요약

| 결정 | 값 |
|---|---|
| 색칠 화면 | 탭이 아니라 push. 내비 숨김. 세션마다 **새 `ColoringController`** |
| 내비 칸 수 | 처음부터 다섯 (`만들기`·`랭크` 는 자리표시자) |
| 작품을 누르면 | **이어 그리기**. 저장된 상태 그대로 연다 |
| 작품별 삭제 | **없다.** 정리는 `내 정보` 의 데이터 초기화로 |
| 썸네일 | 색칠 화면을 **나갈 때 한 번** 굽는다. 없으면 그 도안의 선화로 대체 |
| 카테고리 묶음 | 가로 스크롤 줄이 아니라 **세로 격자** |
| 색칠에서 나갈 때 | 확인하지 **않는다**. 자동 저장이 있어 잃는 것이 없다 (2.3절) |
| 내장 도안 | 4 카테고리 × 3장 = 12장, 코드로 그린 선화 |

**작품별 삭제를 넣지 않는 이유**: 아이에게 영구 삭제는 되돌릴 수 없다. 색칠 안에서는 되돌리기가
지켜 주지만 세션을 넘으면 아무것도 지켜 주지 않는다. 글을 못 읽으니 확인 대화상자도 작동하지
않는다. 작품 하나는 JSON 두 개 + `brush.png`(1024², 실측 88KB) + `thumb.png`(256²) 라
수십 개가 쌓여도 문제가 없고, 브러시를 안 쓴 작품은 그보다 훨씬 작다.
정리는 글을 읽는 사람이 쓰는 `내 정보` 에서 한다.

## 4. 색칠 화면의 생애 — 이월된 버그 셋이 은퇴한다

색칠을 push 로 만들고 **세션마다 컨트롤러를 새로 만들어 pop 에서 버리면**, 후속 문서 세 곳에
"다음 계획이 건드리는 순간 터진다"고 적어 둔 항목들이 **고쳐지는 것이 아니라 발생할 수 없게** 된다.

| 이월 항목 | 왜 사라지는가 |
|---|---|
| 계획 2 후속 §1.1 — `open()` 도중 들어온 탭이 사라진다 | `open()` 이 컨트롤러당 한 번만 불린다. 두 번째 `open()` 이 없다 |
| 계획 2 후속 §3.3 — 두 번째 `open()` 에서 `_prepare()` 가 다시 안 돈다 | 같은 이유 |
| 계획 3 후속 §1.1 — `ageMode` 를 유아로 바꾸면 아이가 갇힌다 | 설정은 별도 화면이고 그때 색칠 화면은 존재하지 않는다. 다음에 열면 새 컨트롤러가 현재 설정을 읽는다 |

셸이 `Settings` 를 들고 있다가 색칠을 열 때마다 넘긴다. 컨트롤러는 그 값을 생성자로 받는다
(이미 그렇게 돼 있다).

**세션마다 `Autosave` 도 새로 만들어야 한다.** `ColoringController.dispose()` 가
`autosave.flush().then((_) => autosave.dispose())` 를 부른다 — 하나를 셸에 두고 돌려 쓰면
첫 세션이 끝나는 순간 `_disposed = true` 가 되고, 그 뒤 `schedule()` 은 **조용히 아무것도
하지 않는다.** 두 번째 작품부터 아이가 칠한 것이 영영 저장되지 않으면서 오류도 뜨지 않는다.
`ArtworkRepository` 는 상태가 없으므로 셸이 하나만 들고 공유해도 된다.

**이 성질은 테스트로 잠근다**(10절) — 구조가 보장하는 것이라도, 나중에 누가 컨트롤러를 셸로
끌어올리면 셋이 한꺼번에 되살아난다.

## 5. 화면 구조

```
KkumulApp
 └ ShellScreen              하단 내비 + 현재 탭
    ├ 놀기                   도안 고르기
    ├ 모아보기                내 작품
    ├ ＋ 만들기               자리표시자 (계획 5)
    ├ 랭크                   자리표시자 (계획 6)
    └ 내 정보                 연령 · 데이터 초기화

ColoringScreen              셸 위에 push. 내비 없음. pop 하면 컨트롤러를 버린다
```

### 5.1 내비는 처음부터 다섯 칸

`만들기` 와 `랭크` 가 아직 없지만 칸은 만든다. 상위 스펙 10.1 이 `만들기` 를 *"중앙의 큰 더하기
버튼으로 분리"* 하라고 해서 그 버튼이 내비 위젯의 구조 자체를 바꾸기 때문이다. 나중에 끼워
넣으면 위젯을 다시 짜고 64dp 기하도 다시 재야 한다.

자리표시자 화면은 그림 하나와 한국어 한 줄이면 된다. 출시 전에만 보이는 화면이다.

**폭 예산**: 다섯 칸 × 64dp = **정확히 320dp**. 여유가 0 이므로 계획 3 의 도구 줄과 같은
주의가 필요하다 — 320×640 에서 실측하는 테스트를 1번 태스크에 넣는다.

### 5.2 세로 예산 (320 × 640, 하단 인셋 34)

| | 탭 화면 | 색칠 화면 |
|---|---|---|
| 앱바 | 없음 (제목은 본문 안에) | 64 |
| 본문 | **542** | 캔버스 350 + 도구 줄 64 + 상황별 128 |
| 하단 내비 | 64 | 없음 |
| 제스처 영역 | 34 | 34 |

탭 화면에 앱바를 두지 않는 것은 본문을 넓게 쓰기 위해서다. 제목은 스크롤되는 본문 맨 위에 둔다.

## 6. 놀기

상위 스펙 10.2 의 네 요소 중 `오늘의 미션 행` 은 계획 6 이라 빠진다.

- **이어 그리기** — 가장 최근에 손댄 작품 하나를 맨 위에 크게. `ArtworkRepository.listAll()` 이
  이미 `updatedAt` 역순으로 준다. 작품이 없으면 이 칸을 통째로 생략한다.
- **오늘의 도안** — 날짜를 씨앗으로 라이브러리에서 하나 고른다. 하루 종일 같고 내일 바뀐다.
  `dohanIds[dayOfEpoch % dohanIds.length]` 로 충분하다 — 난수 상태를 저장할 필요가 없다.
- **카테고리별 도안** — `meta.category` 로 묶어 제목 아래 격자로 펼친다.

**가로 스크롤 줄을 쓰지 않는다.** 계획 3 최종 리뷰가 잡은 결함이 정확히 그것이다 — 가로로
밀리는 줄은 글을 못 읽는 아이에게 "없는 것"이다. 세로 스크롤은 아이도 자연스럽게 한다.

격자는 **2열**로 한다. 320dp 폭에 바깥 여백 12dp 두 번과 칸 사이 8dp 를 빼면 한 칸이
약 **144dp** — 터치 타겟이 넉넉하고 그림이 알아볼 만큼 크다. 3열이면 약 93dp 로 줄어
도안 모양을 분간하기 어려워진다. 정확한 여백 값은 구현 계획에서 정하되 2열은 고정이다.

## 7. 모아보기와 썸네일

내 작품을 최신순 2열 격자로 보여준다. 작품을 누르면 **이어 그리기**로 연다.

작품이 하나도 없을 때는 **빈 상태 안내**를 보여준다(상위 스펙 10.2 의 필수 요소).
글을 못 읽으므로 그림과 한 줄짜리 짧은 문구를 함께 둔다.

### 7.1 썸네일을 언제 굽는가

`thumb.png` 는 새 발명이 아니다 — 상위 스펙 11장의 작품 폴더 구조가 이미
`artwork.json` · `brush.png` · `stickers.json` 과 나란히 적어 두었고, 계획 2·3 이 앞의 셋만
구현했다. 계획 4 가 남은 하나를 채운다. **언제 굽는가만 여기서 정한다.**

**색칠 화면을 나갈 때 한 번.** `ColoringController.close()` 가 이미 그 자리에 있고, 그 순간이
아이가 그 세션에서 그림을 완성한 때다. `close()` 는 생명주기 콜백(앱이 물러날 때)에서도
불리는데, 그때도 굽는 것이 맞다 — 7.2 의 "강제 종료" 경우를 줄여 준다.

**굽는 주체는 컨트롤러가 아니다.** 합성에 필요한 셰이더·영역 텍스처·팔레트 텍스처·선화·
스티커 이미지는 전부 `_ColoringScreenState` 가 들고 있고 컨트롤러는 갖고 있지 않다.
컨트롤러에 옮기는 것은 큰 수술이므로, 이미 있는 패턴을 그대로 쓴다 — `Autosave` 가
`BrushBaker` 콜백을 받는 것처럼 컨트롤러가 **`ThumbnailBaker` 콜백**을 받고, 화면이 텍스처를
다 올린 뒤 자기 굽기 함수를 꽂는다. 콜백이 없으면(텍스처가 아직 없으면) 굽지 않는다.

디바운스마다 굽지 않는 이유는 비용이다. PNG 인코딩은 실측 39ms 고, 계획 3 에서 자동 저장의
브러시 굽기를 "바뀌었을 때만"으로 만들어 그리는 동안의 비용을 0 으로 유지했다. 썸네일을
매초 구우면 그 성과가 무너진다.

썸네일은 **256 × 256** 으로 굽는다. 2열 격자의 한 칸이 약 144dp 이므로 고해상도 화면에서도
충분하고, 1024² 를 그대로 쓰는 것보다 픽셀 수가 16 배 작다.

### 7.2 썸네일이 없으면 선화를 보여준다

앱이 강제 종료되어 `close()` 가 못 돈 경우다. 그 도안의 `lineart.png` 는 에셋으로 항상 있고,
아이는 **그림 모양으로 자기 작품을 알아본다** — 색이 없을 뿐이다.

재생성 로직을 따로 두지 않는다. 다음에 그 작품을 열고 나가면 썸네일이 생긴다.

## 9. 내장 도안 12장

4 카테고리 × 3장. `동물 · 자동차 · 공룡 · 모양`(2.2절).

기존 `flower-01` 이 `모양` 의 한 장이 된다. 그러므로 **새로 그리는 것은 11장**이고,
`flower-01` 은 id 를 유지한 채(저장된 작품이 참조한다) 새 생성기에서 함께 나온다.

**스티커와 다른 것을 그린다.** 스티커는 채워진 도형이었지만 도안은 **선화**다 — 흰 바탕에
검은 윤곽선만 있고 닫힌 영역이 색칠할 자리가 된다. `dohan_cli` 가 그 닫힌 영역을 라벨링한다.

생성기의 본보기는 `app/tools/make_stickers.dart` 가 아니라 **`app/tools/make_sample_lineart.dart`**
다 — `flower-01` 을 만든 그 스크립트이고, 이미 선화를 그린다(`package:image`, 흰 바탕에 굵기
6px 의 검은 윤곽). 새 `make_dohans.dart` 가 그것을 12장으로 일반화하고, 그 자리를 대신한다.
`make_sample_lineart.dart` 는 **지운다** — 자기 헤더에 *"실제 도안 에셋이 준비되면 이 파일은
지운다"* 라고 적혀 있다.

픽셀마다 수식으로 안/밖을 판정하되 **경계선만** 칠한다. 라이브러리의 도형 API 를 쓰지 않으므로
이름을 잘못 짚을 위험이 없다 — 계획 3 에서 `make_stickers.dart` 가 쓴 방법과 같다.

**메타데이터**: `--id`, `--title`(한국어), `--category`, `--difficulty` 를 도안마다 준다.
`regionAnchors` 와 `regionCount` 는 CLI 가 계산한다. `suggestedPalette` 는 CLI 플래그가 없고
기본값이 들어가는데, **읽는 코드가 아직 없다**(팔레트는 계획 3 의 고정 8×3 이다). 그대로 둔다.

에셋은 도안마다 **네 개**다: `lineart.png` · `regions.png` · `meta.json` · `lineart@2x.png`.
넷째는 `buildDohan` 이 *의도적으로* 쓰는 고밀도 기기용 선화다(계획 1 의 선택이고 주석에 이유가
적혀 있다). 다만 **지금은 아무 코드도 읽지 않는다** — `BundledDohanSource` 가 경로를 직접
지정해 `rootBundle.load` 하므로 Flutter 의 배율 변형 해석이 걸리지 않는다. 그대로 둔다:
도구와 싸우지 않고, 2배 선화가 필요해지는 날이 오면 이미 있다. 비용은 장당 약 48KB,
12장이면 번들에 약 580KB 다.

### 9.1 품질 게이트의 실측 창 (2026-10-06 측정)

계획 1 이 `dohan_cli` 를 만든 뒤 아무도 돌린 적이 없었다. 이 설계를 쓰면서 **돌렸다.**
합성 선화 다섯 장을 1024² 로 통과시킨 결과다:

| 입력 | 결과 | 영역 | 배경 | 최소 지름 |
|---|---|---|---|---|
| 동심원 4겹 (= `flower-01`) | 통과 | 4 | 35.4% | 105px |
| 격자 4×4 | 통과 | 16 | 21.5% | 217px |
| 격자 10×10 | 통과 | 100 | 21.5% | 83px |
| 격자 16×16 | **리젝트** | 256 (>120) | 22.1% | 49px (<72) |
| 동심원 3겹, 선 굵기 1px | **리젝트** | 3 (<4) | 51.9% | 121px |

읽어낸 **설계 창**(`QualityThresholds` 의 기본값, CLI 로 바꿀 수 있는 건 `--min-tap-diameter`뿐):

- **칠할 수 있는 영역 4개 이상 120개 이하.** 바깥 배경은 세지 않는다 — 동심원 *n* 겹은
  *n* 개다. 3겹짜리가 거부된 이유가 그것이고, 도안마다 **닫힌 영역을 최소 네 개** 둬야 한다.
- **가장 작은 영역의 내접원 지름 72px 이상.** 격자 10×10(칸 90px)이 83px 로 통과하고
  16×16(칸 56px)이 49px 로 떨어졌으니, 실무 하한은 **칸 90px 안팎**이다.
- **선 굵기는 제약이 아니다.** 1px 선도 `closeLines` 가 닫아 주어 누수가 없었다.
  그래도 보이는 선이 낫다 — 기존 생성기와 같이 **굵기 6px**(반경 3)을 쓴다.
- 배경 비율은 보고만 하고 판정에 쓰지 않는다.

합성 입력이라 사진만큼 험하지 않다 — 종이 질감도 그림자도 없다. **사진 입력의 보정은
아니다**(그건 계획 5 가 실제 선화로 한다). 하지만 12장을 그릴 때 지켜야 할 창은 이것이
전부이고, 위 숫자가 계획 1 후속 문서가 요구한 보정표의 첫 다섯 줄이다.

그래도 게이트에 걸리는 도안이 나오면 **멈추고 보고할 것.** 위 창 안에서 그렸는데도
거부당했다면 임계값이 아니라 파이프라인이 무언가를 놓치고 있다는 뜻이다.

## 10. 테스트 전략

계획 3 에서 비싸게 배운 둘을 앞당긴다.

- **렌더 결과를 읽는 테스트를 넣는다.** 계획 3 에서 테스트 173개가 전부 통과하는 동안 아이가
  손가락을 끌어도 화면에 아무것도 나타나지 않았다 — 전부 컨트롤러 **상태**만 단언했기 때문이다.
  갤러리 썸네일이 실제로 그려지는지는 **픽셀로** 본다.
- **좁은 화면 + 인셋 테스트를 1번 태스크에.** 내비 다섯 칸 × 64dp = 정확히 320dp 로 여유가 0 이다.

그 밖에 반드시 덮을 것:

| 무엇 | 왜 |
|---|---|
| 작품 0개일 때 빈 상태 안내 | 상위 스펙 10.2 의 필수 요소 |
| `thumb.png` 가 없을 때 선화로 대체 | 강제 종료 후의 정상 경로다 |
| 색칠을 열고 닫고 다시 열면 **서로 다른 컨트롤러** | 4절의 은퇴한 버그 셋을 구조로 잠근다 |
| 연령대를 바꾼 뒤 색칠을 열면 그 설정이 적용된다 | 지뢰가 해체됐음을 확인한다 |
| 탭을 오가도 각 탭의 스크롤 위치가 유지된다 | 아이가 갤러리를 보다 돌아오면 처음으로 튀면 안 된다 |
| 썸네일을 굽는 비용이 **나갈 때만** 든다 | 그리는 동안 0 이어야 한다. 호출 횟수로 확인한다 |
| 저장 파일이 깨진 작품을 열면 `-복구-` id 로 열린다 | `main()` 에 있던 복구 경로가 이사 중에 사라지기 쉽다 (11.1절) |
| `dohan build --category=shape` 가 통과한다 | CLI 의 `allowed` 목록을 안 고치면 도안 생성이 거기서 멈춘다 (2.2절) |
| 색칠에서 나갔다 다시 들어오면 채움·브러시·스티커가 그대로다 | 2.3 이 "확인 없이 나가도 된다"고 한 근거 그 자체다 |
| `deleteAll()` 뒤에 `settings.json` 이 남는다 | 작품만 지운다 (8절) |

### 11.1 `main.dart` 를 옮길 때 잃기 쉬운 것

지금 `main()` 은 `runApp` **전에** 컨트롤러를 만들어 열고, 그 과정에 두 겹의 복구가 들어 있다:

1. `SettingsStore.load()` 실패를 잡아 기본 연령대로 시작한다 — 설정 파일 하나 때문에 앱이
   영영 안 뜨는 일을 막는다.
2. `controller.open()` 실패를 잡아 **`<id>-복구-<timestamp>`** 라는 다른 id 로 다시 연다 —
   아이는 계속 칠할 수 있고, 잠깐 못 읽었을 뿐일지 모르는 원본은 덮어쓰지 않는다.

셸에서는 작품을 여는 시점이 `main()` 이 아니라 **탐색 시점**으로 옮겨간다. 2번 복구 경로도
같이 옮겨야 한다 — 그냥 두고 오면 저장 파일이 한 번 깨졌을 때 아이가 그 작품을 영영 못 연다.
1번은 `main()` 에 남는다(설정은 여전히 시작할 때 한 번 읽는다).

`ColoringScreen` 도 지금은 **이미 열린** 컨트롤러를 받는다. 라우트가 컨트롤러를 만들어 열고
pop 에서 버리는 구조로 바뀌므로, 여는 동안의 로딩 표시가 새로 필요하다.

새 파일 9개 + 고치는 파일 6개 + 지우는 파일 1개. 계획 3(새 11 + 고침 7)과 비슷한 규모다.
